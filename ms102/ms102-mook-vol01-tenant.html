CARD 01 / 10テナントとドメイン

テナントを作ったあと、変えられないものは？

器の形は、最初に決まる。

テナントを作ると、裏側に Microsoft Entra ID のディレクトリが1つ作られます。両者は1対1で切り離せません。いくつかの項目は作成時に決まって後から変えられず、「変えたい」と言われたら答えは新しいテナントへの移行です。

押さえどころ
  • ドメインを削除できないときは、そのドメインを使うユーザーの UPN・グループのメール アドレス・アプリの応答 URL・プロキシ アドレスを別ドメインに付け替える。
  • SPF は TXT レコード1つに1行でまとめ、v=spf1 を必ず先頭に置く。複数あると正しく機能しない。
  • 認証を Entra ID が行うのがマネージド（クラウド専用・PHS・PTA）、AD FS などに任せるのがフェデレーション。種類は Get-MgDomain の AuthenticationType で確認する。
ここが出る！答えを思い出してから押す
テナントの国／地域や初期ドメインの名前を変えたい

変更できない。新しいテナントを作って移行する

カスタム ドメインを削除しようとしたら失敗した。まず何をする？

そのドメインを UPN やプロキシ アドレスに使っているユーザー・グループの参照を別ドメインに付け替える

SPF が正しく機能しない。よくある原因は

SPF の TXT レコードが複数ある・分割されている。1行にまとめ、v=spf1 を先頭に置く

TXT で所有権を確認したのに、そのドメイン宛てのメールが届かない

検証とサービス用の DNS 構成は別。MX レコードを設定する

CARD 04 / 10Microsoft 365 Backup

ランサムウェアで暗号化された数千のサイトを、短時間で戻すには？

戻すならバックアップ、
消させないなら保持。

Microsoft 365 Backup は、SharePoint・OneDrive・Exchange のデータを Microsoft のサービス境界の中でバックアップし、指定した時点へまとめて戻すサービスです。ユーザー ライセンスではなく、保護するデータ量に応じた従量課金で動きます。

押さえどころ
  • E5 を買えば使えるわけではない。前提は従量課金の構成。
  • バックアップはサービス境界の外に出ない。外部ストレージへのエクスポートではない。
  • 版の履歴から1件ずつ戻す方法は、数千サイト規模では「短時間で」の要件を満たさない。

CARD 05 / 10ユーザーと退職者の処理

退職者のサインインは止めた。ライセンスを外す前にやることは？

ライセンス解放と削除は、いちばん最後。

ユーザーは管理センター、Entra 管理センター、PowerShell、ディレクトリ同期、B2B 招待で作れます。ライセンスを配る前提は「使用場所」の設定です。退職者の処理には Microsoft が推奨する順番があり、データへの道筋を先に確保します。

押さえどころ
  • 使用場所（Usage location）が未設定だと、ライセンスの割り当ては失敗する。
  • 削除したユーザーは30日間復元できる。過ぎると完全に削除される。
  • 同期されたユーザーの属性は、クラウド側ではなくオンプレミス AD 側で変える（VOL.02 で詳しく）。

CARD 06 / 10グループと共有メールボックス

その目的に合うグループはどれ？

グループは、用途で選ぶ。

グループは種類が多く頻出です。共同作業の箱、権限とライセンスを配る相手、一斉メールの宛先、共有の受信箱。何のために使うかで選べば迷いません。配布グループを Microsoft 365 グループにアップグレードできるかどうかは、不可の条件で消していくのが速い解き方です。

押さえどころ
  • 動的メンバーシップ・グループの有効期限ポリシー・名前付けポリシーはEntra ID P1。期限切れで消えたグループは30日間復元できる。
  • アップグレードは、メールボックスを持つExchange 管理者が要求を送り、所有者が承認する。所有者が自分ではできない。メール アドレスは変わらない。
  • 条件を満たしているのに失敗するなら、Microsoft 365 グループ向けのカスタム メール アドレス ポリシーを疑う。

CARD 07 / 10ライセンス管理

ライセンスの割り当てが失敗する。何を疑う？

まず使用場所を疑う。

ライセンスは直接割り当てか、グループ ベース ライセンスで配ります。グループにライセンスを付けると、メンバーに自動で継承され、外れると自動で剥がれます。規模が大きいほど有利ですが、固有のつまずきが4つあります。

押さえどころ
  • グループ ベース ライセンスにはEntra ID P1 以上が必要。E3・E5・Business Premium に含まれる。
  • 「特定のユーザーだけ Exchange を外したい」も、ユーザー側ではなくグループ側で制御する。
  • 保有ライセンスと空き数は Get-MgSubscribedSku で確認できる。

MSOnline と AzureAD は、もう使えない。

CARD 09 / 10ロールとロールグループ

パスワードを戻せるのは誰？ 最小特権ならどのロール？

答えは、いちばん狭いロール。

設問の多くは「最小特権の原則に従うと、どのロールか」です。全体管理者が正解になることはまれです。Entra のロールと、Purview や Exchange のロールグループは別系統で、Entra から Purview へは権限が流れ込みますが、逆は流れません。

押さえどころ

  • 「部署のデータだけに限って」コンプライアンス権限を渡すなら、Entra ロールではなくPurview のロールグループ（必要なら管理単位でスコープ）。
  • 検索結果のメールを一括削除する Search And Purge は、既定で組織管理ロールグループにしかない。

CARD 10 / 10管理単位と PIM

権限の「範囲」を絞る？ 「時間」を絞る？

範囲は管理単位、時間は PIM。

管理単位は、ディレクトリの一部を切り出してロールの効く範囲を絞る仕組みです。PIM は特権ロールを常時持たせず、必要なときだけ時限で有効にする仕組みです。必要なライセンスは、管理単位が P1、PIM が P2 です。

押さえどころ
  • 制限付き管理単位にすると、スコープされた管理者以外はテナント全体のユーザー管理者でも変更できない。役員アカウントの保護に使う。
  • 管理単位は Entra 管理センターで作る。作成には特権ロール管理者以上が必要。
  • 「支社ごとに管理者を分けたい」なら管理単位、「支社ごとにライセンスを配りたい」なら動的グループ。
ここが出る！答えを思い出してから押す

大阪支社のユーザーを含む管理単位を作り、そこにスコープしてヘルプデスク管理者を割り当てる

AU1 にグループ G1 を追加し、User2 に AU1 スコープのパスワード管理者を付けた。G1 のメンバーの PW は戻せる？

戻せない。メンバーを AU1 に直接追加する必要がある
